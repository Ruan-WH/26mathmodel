# 赛题分析与逐题建模

如需通用规范，读取 `../_references/math_modeling_norms.md` 中与题型、假设和建模有关的小节。

## 边界

- 可以一次性识别全部顶层子问题、输入输出和依赖接口，但只详细求解当前问题 i。
- 当前问题完成代码、图和对应正文并经用户批准后，才详细建模下一题。
- 后续问题只记录依赖、潜在方法和风险，不预填数值、不提前下结论。

## 工作流

1. 只把题面明确编号的顶层问题作为子问题，并为每问形成“场景/对象变化—关键机制与约束—建模目标—预期输出”的简短分析性概括，供论文“问题提出”使用。该概括必须重组题意，不能逐句复制题面，也不能提前给出模型公式、算法细节或数值结论。
2. 盘点附件字段、单位、缺失、异常、重复和可用样本范围。
3. 对模糊表述列出合理解释，用量纲、边界情形或快速验算筛选。
4. 为当前问题写清目标、变量、参数、假设、目标函数、约束、算法、输入输出、停止条件和校验方法。
5. 检查模型是否可识别、可计算，极端情况下是否符合常识，是否错误使用未来信息。
6. 增量更新 `reports/ANALYSIS_MODELING_REPORT.md`，随后交给 `3coding-visual`，不继续下一题。

当前问题报告至少包含：目标与评价标准、数据与已知条件、歧义和假设检验、符号变量、数学模型、算法与停止条件、接口、校验与失败判据、代码任务清单。所有结论须回溯到题面、附件或明确假设。

## 优化模型汇总

当前问题属于优化、调度、分配或控制时，在分别推导目标函数和各类约束后，必须再给出一个可直接交给求解器的完整汇总模型。汇总不能只写“目标函数 + 约束见前文”，应逐项覆盖实际实现中的：

- 决策变量及连续、整数、0-1 属性和上下界；
- 状态转移、运动学、守恒或变量间耦合关系；
- 容量、资源、时序、间隔、时间窗、空间位置和边界约束；
- 可行性、安全性、物理有效性及终止条件；
- 目标函数中集合、指示变量、区间并集或辅助变量的定义。

报告中使用统一的大括号或等价的分组数学结构呈现该模型，并在每行后保留必要的适用索引或物理含义。约束很多时可按“变量域—状态方程—业务约束—有效性判据”分组编号，但不能为增加篇幅而重复同一约束或引入代码中不存在的装饰性条件。汇总式之后说明活跃约束、松弛约束和求解器实际处理方式，确保数学模型、代码接口与验证清单一一对应。

全题结构部分还应给出一段总体任务概括，并说明各问如何从基准计算递进到参数优化、多弹时序、多机协同和多目标资源分配；这种依赖分析用于转述问题，不等同于提前求解后续问题。
