# 数学建模逐题工作流

本 skill 负责启动和调度，不代替下游专业 skill。

## 不可跳过的交付方式

先梳理全部顶层子问题及依赖，但不得一次性给出全部求解结果。随后对问题 i 严格执行：

```text
详细建模 -> 代码求解、校验与数据图 -> 必要的 DrawIO 图
-> 对应论文正文 -> 局部编译与一致性验收 -> 停止，等待用户审查
```

只有用户明确批准问题 i，才能开始问题 i+1。用户要求修改时留在当前循环，更新所有受影响的模型、代码、结果、图和正文，重新验收后再次停止。摘要、总体结论、模型总评和最终验收仅在全部子问题获批后进行。

## 初始化

创建或更新 `plan.md` 与 `todo.md`。只询问会改变求解路线的关键信息；本项目排版固定为 `5writing` 捆绑的 CUMCM 1.1.0 LaTeX 模板，不再询问 Typst/LaTeX。

`plan.md` 至少记录：题目与附件、顶层子问题数量、依赖关系、当前问题、数据风险、用户确认的关键假设和每题审查状态。顶层问题梳理还要为每问保留“场景变化、关键约束、建模目标、预期输出”的简短概括，供 `5writing` 写成分析性的“问题提出”，不得直接复制题面。

`todo.md` 按题记录建模、代码与数据图、DrawIO、论文正文、待审查、已批准。状态只允许 `未开始 / 处理中 / 待审查 / 已批准`，不能用一个总阶段勾选掩盖逐题进度。

论文结构始终遵循 `5writing` 的固定章节层级：问题重述与问题分析分开，模型假设、符号说明、模型准备各自作为一级标题，五个子问题分别使用“问题 i 模型建立和求解”一级标题；不得因逐题推进而把当前问题临时提升到错误的章节位置。

## 调度

1. `2analysis-modeling`：总体依赖梳理 + 当前问题详细模型。
2. `3coding-visual`：当前问题代码、结果、验证和 Nature 风格数据图。
3. `4drawio`：当前问题必要的黑白流程/结构/判断图。
4. `5writing`：按指定模板写当前问题正文并编译。
5. `6verity`：执行当前问题局部验收。
6. 向用户交付当前问题的结论、文件和预览，随后停止。

没有明确批准不得把“继续优化”“看起来可以”等含糊反馈解释为进入下一题的授权。
