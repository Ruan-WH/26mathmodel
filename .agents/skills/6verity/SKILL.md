# 验证与验收

本 skill 不重新设计模型或制造新结果，只验证、修复确定性的实现/排版错误并记录证据。

## 两种模式

### 当前问题局部验收

在问题 i 正文完成后执行，只检查当前问题及其公共依赖：

- 代码能从记录的入口复现关键数值，随机种子和环境已记录。
- 约束、单位、范围、误差指标和舍入在代码、报告、正文、表图中一致。
- 数据图符合 Nature 风格且无裁剪、乱码、遮挡和误导性坐标。
- DrawIO 为黑白灰、粗线、紧凑布局，判断分支完整，连接线不穿越节点。
- 对应正文没有未验证结论，公式、图表和引用均能编译解析。
- 枚举当前问题全部 `fig:`、`tab:` 标签，确认每个图表都在相邻正文中被 `\cref` 或 `\ref` 明确引用，并有针对其趋势、阈值、分图、区间、关键参数或约束状态的实质解释；只有标题或一句无分析的“见图/表”不算通过。
- 对优化类问题逐项比对“优化模型汇总”与代码：目标方向、变量类型、上下界、状态耦合、容量或时序或空间或物理约束、辅助定义和终止边界不得遗漏或写反；汇总式应使用清晰的大括号分组，且不能包含实现中未兑现的装饰性约束。

将问题 i 状态更新为“待用户审查”，随后停止；本 skill 无权批准或进入下一题。

### 最终验收

仅在所有问题均被用户标记“已批准”后执行：复跑完整项目，检查跨问题依赖、摘要与结论一致性、参考文献、附录、提交文件和最终 PDF。任何未批准问题都会阻止最终验收。摘要还必须符合 `../5writing/references/award-abstract-style.md`：按“总述段 + 每问独立段 + 验证推广段”组织，五问时恰为七段且各问题段以加粗的“针对问题 X：”开头；通常 600--850 个中文字（五问可约 900 字），含 5--9 处克制强调、统一三位小数和 4--6 个关键词。

最终验收还必须确认：参考文献之前存在与实际使用情况一致的“AI工具使用声明”；若声明使用了 AI，支撑材料中有工具名称、使用环节、用途和人工核验记录。附录仅按 A“支撑材料文件列表”、B“完整源程序”排列，附录 A 所列文件真实存在且用途准确，附录 B 与实际运行源码一致，不得残留模板示例或用伪代码冒充完整程序。

## CUMCM 模板检查

- `paper/` 源自 `5writing/assets/cumcm-1.1.0.zip`。
- 保留 `commons/cumcmthesis.cls`、字体和原目录结构；主类选项为 `withoutpreface,bwprint`，无目录，无 `draft`。
- 使用 xelatex/latexmk 编译；无缺图、未定义引用、严重 overfull、乱码或空白异常页。
- 渲染 PDF 页面做视觉检查，不能只看编译退出码。
- 全文图表标签与正文引用必须一一对应：不存在未引用图表、悬空引用或错误编号；图表附近的分析文字与实际图形、表中数据一致，且引用不因浮动跨节而产生歧义。
- 检查 `main.tex` 的顺序为：正文、AI工具使用声明、参考文献、附录 A、附录 B；AI 声明和参考文献均使用不编号标题，附录编号连续且不出现附录 C。

## 报告

增量写 `reports/VERIFY_REPORT.md`，每个问题记录检查命令、关键复现值、通过项、失败项、修复和待用户决定事项。最终给出 `PASS / FAIL / BLOCKED`；只有所有硬门槛通过才可标 `PASS`。
